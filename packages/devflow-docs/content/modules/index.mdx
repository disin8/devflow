DevFlow ships **50 modules** in **10 categories**. Each module is an independent unit: it can be applied on its own, it never overwrites a file that already exists, and every page below lists the exact artefacts it produces.

```bash
# Apply a single module
npx create-devflow --only eslint

# Preview a single module without touching the project
npx create-devflow --only eslint --dry-run
```

## How to read these pages

Each module page follows the same structure so you can compare them quickly:

1. **The problem** — what breaks when you configure this by hand
2. **The command** — the exact invocation
3. **Generated files** — the real file contents, not a summary
4. **Packages and scripts** — what ends up in `package.json`
5. **Manual setup** — what the equivalent hand-written configuration looks like
6. **Limits** — what the module does *not* do
7. **FAQ** — the objections people actually raise

## Conflicts

Some modules replace each other and cannot be applied together. The interactive wizard blocks the conflicting pairs, and `--only` accepts a single id so you cannot create the conflict by accident:

| Pair | Use instead of |
| --- | --- |
| Husky ↔ Lefthook | Pick one hook manager |
| ESLint + Prettier ↔ Biome | Biome replaces both |
| Vitest ↔ Jest | Pick one test runner |
| Playwright ↔ Cypress | Pick one E2E runner |
| Renovate ↔ Dependabot | Pick one update bot |
| release-it ↔ semantic-release | Pick one release driver |
| Nx ↔ Turborepo | Pick one build system |
