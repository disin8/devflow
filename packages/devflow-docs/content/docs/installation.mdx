## Requirements

- **Node.js** >= 18.0.0 — 18, 20 and 22 are supported and tested
- A JavaScript or TypeScript project with a `package.json` (DevFlow reads it to detect the package manager and the stack)
- macOS, Linux, or Windows through WSL2
- A Git repository, if you want the Husky hooks to be active

DevFlow has no native binary dependencies, so there is nothing to compile and no platform-specific download.

## Using npx (Recommended)

No installation required — run it directly:

```bash
npx create-devflow
```

This always fetches the latest published version.

## Global Installation

```bash
npm install -g create-devflow
```

Then use it anywhere:

```bash
devflow
# or
create-devflow
```

## Project-Local Installation

If you want to pin the version in your project:

```bash
npm install -D create-devflow
```

Add a script to `package.json`:

```json
{
  "scripts": {
    "devflow": "devflow"
  }
}
```

This is the right choice in a repository that generates its own workflow, because the version is pinned in the lock file and every machine runs the same one.

## Verify Installation

```bash
devflow --version
devflow --help
```

`--version` prints the published version of the package you are running — it reads it from the installed `package.json`, so it always matches what npm gave you.

## Package Managers

DevFlow works with all major package managers. The package manager is detected from the lock file, and every generated file — the CI workflow, the Dockerfile, the install commands — is written for the detected manager.

| Package manager | Run DevFlow with | Lock file used in the generated files |
| --------------- | ---------------- | ------------------------------------- |
| **npm**         | `npx create-devflow` | `package-lock.json` |
| **pnpm**        | `pnpm dlx create-devflow` | `pnpm-lock.yaml` |
| **yarn**        | `yarn dlx create-devflow` | `yarn.lock` |
| **bun**         | `bunx create-devflow` | `bun.lock` |

Override the detection when you need to:

```bash
devflow --pm pnpm
```

## Package managers in the generated configuration

| Package manager | Install command in CI | Script prefix | Notes |
| --------------- | --------------------- | ------------- | ----- |
| npm | `npm ci` | `npm run` | Uses the frozen lock file, so the CI build fails if the lock file is out of date. |
| pnpm | `pnpm install --frozen-lockfile` | `pnpm run` | Corepack is enabled first, so the pnpm version comes from the `packageManager` field. |
| yarn | `yarn install --frozen-lockfile` | `yarn run` | Corepack is enabled first. |
| bun | `bun install --frozen-lockfile` | `bun run` | Bun is installed by `oven-sh/setup-bun`; there is no `node_modules` cache to restore. |

The `run` prefix is always explicit, because `bun build` is Bun's bundler rather than the `build` script in your `package.json`.
